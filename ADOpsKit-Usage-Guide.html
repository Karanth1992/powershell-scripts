ADOpsKit — PowerShell Module for Active Directory Operations

ADOpsKit is a PowerShell Gallery module that packages ten commonly needed Active Directory operations into a single install — DC health checks, replication topology diagrams, GPO inventory, LDAP security auditing, account lockout tracing, and Entra Connect sync monitoring. Most functions work without ADWS, using native LDAP and repadmin directly.

By K Shankar R Karanth PowerShell ADOpsKit · Usage Guide
Quick idea: Install ADOpsKit once from the PowerShell Gallery and get ten ready-to-run Active Directory functions. No third-party dependencies, no CDN calls — everything works in an air-gapped environment.
Health

DC health reports, port tests, and performance baseline deployment across the forest.

Audit

Account lockout tracing and insecure LDAP bind detection via event log analysis.

Inventory

AD architecture assessment, replication topology diagrams, and GPO inventory reports.

Installation

Install ADOpsKit directly from the PowerShell Gallery. No manual download or cloning required. 

# Install for the current user — no admin rights needed
Install-Module ADOpsKit -Scope CurrentUser

# Install system-wide — requires Run as Administrator
Install-Module ADOpsKit -Scope AllUsers

# Verify the install and list all available functions
Get-Command -Module ADOpsKit

If you are on Windows Server 2016, 2019, or 2022 with a restricted TLS configuration, run the following line first. Without it, the Gallery connection will fail with an SSL error. 

[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
Install-Module ADOpsKit -Scope CurrentUser
Permanent TLS fix: To avoid setting this every session, write it to the registry: Set-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\.NETFramework\v4.0.30319' -Name 'SchUseStrongCrypto' -Value 1 -Type DWord

Get-ADReplicationTopologyDiagram

Generates a fully self-contained HTML file with an SVG diagram of your AD replication topology. The PDC Emulator sits in the centre. All other DCs arrange themselves in a circle around it. Site membership is colour-coded per box. Replication health is shown per link arrow.

This function uses LDAP on port 389 and repadmin.exe only. No AD PowerShell module, no WinRM, no ADWS. It runs from any domain-joined machine.

Gold border

PDC Emulator — centre node of the diagram.

Blue border

Standard domain controller with healthy replication.

Red border

Domain controller with one or more replication failures.

# Generate with default output path
Get-ADReplicationTopologyDiagram -OutputPath "C:\temp\topology.html"

# Target a specific DC to query
Get-ADReplicationTopologyDiagram `
    -DomainController "DC01.corp.contoso.com" `
    -OutputPath       "C:\Reports\ADTopology.html"
How it works: DC inventory comes from the CN=Sites,CN=Configuration LDAP container. Replication partnerships come from repadmin /showrepl * /csv which uses DRSR/RPC — the same protocol DCs use to replicate. Multiple CSV rows per DC pair (one per naming context) are deduplicated to one arrow per directed pair.

Get-ADForestHealth

Produces a colour-coded HTML health report for every DC across the entire forest. Discovers all domains, queries each domain's PDC Emulator via Invoke-Command, then collects hardware metrics on individual DCs via WMI — so WinRM is only needed on PDC Emulators, not on every DC. 

# Run with defaults — report written to OutputFolder
Get-ADForestHealth

# Write report to a network share
Get-ADForestHealth -OutputFolder "\\fileserver\Reports\ADHealth"

DCDiag tests run per DC: Connectivity, DFSREvent, KccEvent, FSMOCheck, NetLogons, Replications. Hardware metrics collected: OS drive free space (GB), CPU usage (%), memory usage (%), uptime (days).

Test-DCPortHealth

Tests all critical Active Directory TCP ports against every DC in the domain using async TCP connections with a configurable timeout. Unreachable hosts do not hang the script. Output is a colour-coded console table with an optional CSV export. 

# Default 3-second timeout
Test-DCPortHealth

# Custom timeout with CSV export
Test-DCPortHealth -TimeoutSeconds 5 -ExportPath "C:\temp\DCPortHealth.csv"
Authentication ports

88 Kerberos · 464 Kerberos PW · 53 DNS

Directory ports

389 LDAP · 636 LDAPS · 3268 GC · 3269 GC-LDAPS

Infrastructure ports

135 RPC · 139/137/138 NetBIOS · 445 SMB · 3389 RDP

Get-AccountLockoutReport

Queries all currently locked AD accounts, then searches Security Event ID 4740 on the PDC Emulator to identify which computers triggered each lockout. Produces three report formats — plain text, CSV, and HTML — and copies them to a shared path. 

# Default paths, 7-week event lookback
Get-AccountLockoutReport

# Custom paths, 24-hour lookback
Get-AccountLockoutReport `
    -TempPath             "D:\temp" `
    -SharedPath           "\\fileserver\Reports\Lockouts" `
    -LookbackMilliseconds 86400000
Run as a scheduled task: Schedule this hourly on a domain-joined admin server. Point -SharedPath to a monitored file share and you have a continuous lockout audit trail with no SIEM required.

Get-InsecureLDAPBinds

Detects clients performing unsigned or simple LDAP binds by reading Event ID 2889 from the Directory Service log on every DC. This is the essential pre-check before enforcing LDAP signing via Group Policy — unsigned bind sources will fail authentication after enforcement. 

# Check last 24 hours across all DCs
Get-InsecureLDAPBinds

# Check last 72 hours, export to custom folder
Get-InsecureLDAPBinds -Hours 72 -OutputPath "C:\temp\LDAPBinds"
Before enforcing LDAP signing: Run this with -Hours 168 (one full week) to catch infrequent binds from scheduled tasks, legacy applications, and monitoring agents before you block them via GPO.

Get-GPOInventory

Generates a full GPO inventory for a domain as a styled HTML report. For every GPO it collects: creation and modification timestamps, OU links including domain root, computer and user settings status, applied permissions and trustees, and WMI filter name and query. 

Get-GPOInventory -DomainName "corp.contoso.com"

# Custom output path
Get-GPOInventory `
    -DomainName "corp.contoso.com" `
    -OutputPath "D:\Reports\GPOInventory.html"

Get-GPOInventoryWithSettings

Extended GPO inventory that parses the raw XML from Get-GPOReport to extract the actual configured settings inside each GPO — not just metadata. Produces a detailed HTML report with one row per configured setting across all GPOs in the domain. 

Get-GPOInventoryWithSettings -DomainName "corp.contoso.com"

# Custom output
Get-GPOInventoryWithSettings `
    -DomainName "corp.contoso.com" `
    -OutputPath "D:\Reports\GPOWithSettings.html"
Use case: Run this before a migration or domain consolidation to get a complete picture of every configured setting across your GPO estate — without opening GPMC one GPO at a time.

Get-ADArchitectureAssessment

Comprehensive AD inventory covering domains, domain controllers, users, computers, groups, OUs, sites, site links, replication health, GPOs, port availability, and services running on DCs. Outputs HTML, JSON, and CSV to a single folder. 

Get-ADArchitectureAssessment `
    -DomainName   "corp.contoso.com" `
    -OutputFolder "C:\temp\ADAssessment"
Use for handover documentation: Run this when taking over a new environment. The HTML output is a board-ready architecture summary. The JSON can be ingested into monitoring tools or a CMDB.

Enable-DCPerformanceBaseline

Remotely creates and starts a logman Data Collector Set on every DC in the domain via WMI Win32_Process. No PSRemoting required. Captures CPU, memory, disk, network, NTDS, and LDAP counters at 5-minute intervals into a circular binary log capped at 500 MB per DC. 

# Deploy to all DCs in the current domain
Enable-DCPerformanceBaseline

Counters collected per DC:

  • \Processor(_Total)\% Processor Time
  • \Memory\Available MBytes and \Memory\Pages/sec
  • \LogicalDisk(_Total)\% Free Space
  • \PhysicalDisk(_Total)\Disk Reads/sec and Writes/sec
  • \Network Interface(*)\Bytes Total/sec
  • \NTDS\LDAP Searches/sec
  • \NTDS\DS Directory Reads/sec and DS Directory Writes/sec
Safe to re-run: If a Data Collector Set already exists on a DC the function issues a warning rather than an error. Logs are stored locally on each DC under C:\PerfLogs\DC_Baseline\.

Get-EntraConnectSyncStatus

Reports the health and sync status of an Entra Connect (Azure AD Connect) server. Runs locally on the sync server or remotely via WinRM. Collects last sync cycle time and result, connector export and import error counts, password hash sync status, staging mode state, auto-upgrade setting, and pending export object counts. 

# Run on the Entra Connect server itself
Get-EntraConnectSyncStatus

# Run against a remote Entra Connect server
Get-EntraConnectSyncStatus -ComputerName "AADCONN01"

# Export connector statistics to CSV
Get-EntraConnectSyncStatus `
    -ComputerName "AADCONN01" `
    -ExportPath   "C:\temp\EntraConnectStatus.csv"

Updating and Managing the Module

# Check installed version
Get-Module ADOpsKit -ListAvailable

# Update to the latest version
Update-Module ADOpsKit

# Check available versions on PSGallery
Find-Module ADOpsKit -AllVersions

# Remove the module
Uninstall-Module ADOpsKit
